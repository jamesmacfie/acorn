What improved

  • Ownership: GitHub owns repository reads, routes, device flow, and feature styles; core keeps generic contracts.
  • Runtime: capability IDs replace provider-shaped module globals; the bridge is now a narrow route adapter and test seam.
  • Data: notes has a current namespace; core’s shared external-item read model is documented as deliberate.
  • Change shape: 788-line DiffView became a stable wrapper plus focused diff modules; compatibility facades preserve imports.
  • Validation: control frames, pairing responses, JSON-RPC, signed claims, run targets, and persisted data have explicit schemas.

Test and API impact

  • Passed: full lint 23/23; arch 22/22; client-core 298/298; GitHub 80/80; agents 162/162; workflows 20/20; protocol 45/45; Docker 32/32; notes 24/24.
  • Added: characterization coverage for Linear, Rollbar, Docker, database, notes, terminal routes, agent profiles, source/route registries, repository contracts, and schema fallbacks.
  • API: route shapes stay stable except the current notes namespace, whose memory path remains a compatibility alias.
  • Runtime/deploy: both Node hosts share graph/reconcile/drain composition; no Electron dependency entered the shared assembly.

Costs and residual risk

  • Live desktop QA: loopback server tests fail with listen EPERM in this sandbox; PTY coverage fails with posix_spawnp failed. Run desktop boot, terminal attach, source switching, route navigation, and two-node restart QA in a normal desktop environment.
  • Compatibility: old memory routes, protocol agent projections, and test-only route capability overrides remain intentionally bounded seams. Remove them on their documented release/migration schedule.
  • Git state: the linked worktree index lock is unavailable, so changes are not committed or staged in this audit.
  • Next slice: add real Electron smoke evidence, then remeasure and stage the migration so Git can record renames and per-slice history.
