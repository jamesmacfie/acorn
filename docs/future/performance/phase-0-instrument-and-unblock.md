# Phase 0: instrument, and unblock the build

Status: **shipped 2026-09-02.** The icon set is split (77 eager names, generated and lint-checked), both
hosts' build checks carry a byte ceiling and a name denylist, and the node, the helper, the renderer and
the terminal client each print their own boot account. The renderer's startup budget is green at
974,732 B, down from 1,329,679 B. Numbers in [measurements.md](./measurements.md); behaviour in
[frontend.md](../../frontend.md) § Startup budget, [ui-design.md](../../ui-design.md) § Icons and
[local-development.md](../../local-development.md) § Timing a cold start.

Two things this phase could not do, both because they need the app running rather than built: nobody
has read the desktop's four boot accounts side by side, and nobody has read the git or SQLite histograms
against real traffic. Phase 2 and phase 5 own those readings; measurements.md says so in its own words
rather than carrying a made-up figure.

One deliberate change of shape: the `TimeToFirstDraw` renderable is still exported by `@opentui/solid`
0.5.9, but it is an on-screen label rather than a headless timer — using it would paint a debug overlay
over the shell. The renderer's own first `frame` event is the same moment with nothing drawn.

## Goal

The desktop build passes its startup budget again, and neither host can drift back over it without a
named chunk failing the build. Both hosts and the node print a cold-start timeline a person can read.
The node can print a duration per request when asked. After this phase the programme argues from
numbers, which the rule at the top of [analysis.md](./analysis.md) requires and nothing yet supplies.

## Why this phase, and why now

`pnpm --filter @acorn/desktop build` runs `apps/desktop/scripts/check-renderer-budget.mjs`, which
sums the bytes of every script the built `index.html` loads or preloads. On 2026-08-31 it reported
1,317,605 bytes against a 1,250,000 limit. On 2026-09-02, after 31 unrelated commits, it reported
1,324,279. A red build that stays red for two days stops being a signal, and a byte budget alone lets
the next heavy chunk in as long as something else shrank.

The one fix known to turn it green is the icon set. `packages/client-core/src/kit/tokens/iconNodes.ts`
imports `lucide-static/icon-nodes.json` whole, 1,756 icons and 706 KB of JSON that minify to a 371 KB
chunk, because `packages/client-core/src/kit/components/content/Icon.tsx` resolves `props.name`
against the map at render time and the bundler cannot see which names are reachable. Sixty-eight
names appear as literals in the tree. The rest must stay reachable: a person can assign any icon to a
task, a plugin manifest can name any one, and both choices are persisted, so a build-time census would
break stored data (refused.md § Dropping unreferenced icons).

Measurement is the other half. The repo has more timing than the first read knew, and less than the
programme needs. `apps/node/src/composition/runtime.ts` has `bootTimer()`, which prints
`[service:boot] <label> +<ms>ms` for migrate, install, listener-up, and each reconcile step.
`packages/client-core/src/infra/persistence/startupRestore.ts` marks the cache restore with
`performance.mark`. The terminal client has nothing, and `@opentui/solid` exports a `TimeToFirstDraw`
renderable nobody uses. No request on the node is timed. No git spawn or SQLite statement is timed.

## Scope

In:

- The icon split. A 12 KB eager map of the 68 code-referenced names, generated by a script that
  scans the tree for literal icon names so the list cannot rot, and the full map behind
  `() => import('lucide-static/icon-nodes.json')`. `Icon` reads the eager map first and the lazy one
  once it resolves. `IconPicker` and anything drawing `tasks.icon` await the lazy map, so a
  user-picked name never flashes as its own text.
- A startup denylist in `check-renderer-budget.mjs`: chunk-name prefixes that fail the build when
  they appear in the script or preload list even under budget. Start with `shiki`, `wasm`,
  `DiffPane`, `prModel`, `viewState`, and the full icon chunk once the split gives it a name of its
  own. Phase 1 is what makes the first four pass; the list lands here so phase 1 has a test to turn
  green.
- `apps/tui/scripts/check-startup-graph.mjs` (new): walks `from "./chunks/..."` and `import
  "./chunks/..."` edges from `dist/chunks/App-*.js`, sums the closure, and fails over a byte ceiling
  or on the same denylist. Run from the TUI's `build` script after `vite build`. Set the ceiling at
  the measured 1.06 MB so it holds the line until phase 1 lowers it.
- Boot marks. Node: extend `bootTimer()`'s labels with the login-shell probe, each plugin's `init`
  and `ready`, cert load, and bind, and keep it unconditional; it is one line per label. Helper
  (`apps/desktop/src/helper/helperMain.ts`, `packages/custody/src/index.ts`): cache sweep, bundled
  rewrite, `service.start`, WebSocket bind, ready line, on stderr behind `ACORN_PERF=1`. Renderer
  (`apps/desktop/src/client/index.tsx`): `performance.mark` at script start, after the two awaits,
  at first paint, and at `nodeReady`. Terminal client (`apps/tui/src/main.tsx`): `TimeToFirstDraw`
  plus marks around `openNode`, `import('./App')`, `readJson(tasks)`, and `createCliRenderer`,
  printed after `renderer.destroy()` alongside the held warnings, because stderr is the screen while
  the renderer owns it.
- One request-duration line on the node behind `ACORN_PERF=1`: method, path pattern, status,
  milliseconds, in the request-id middleware in `packages/node-core/src/server/respond.ts` where the
  id is minted. Plus a `process.hrtime` histogram on the git seam
  (`packages/node-core/src/server/core/git.ts`) and the SQLite shim
  (`packages/node-core/src/server/storage/sqlite.ts`), dumped on `SIGUSR2` or at drain.
- A depth count of the modulepreload chain, printed by the budget script, since the first read
  argued 143 requests through the scheme handler is a waterfall and nothing measures it.

Out: any change to what loads, beyond the icon split. Every other byte waits for phase 1.

## Design

**The eager icon map is generated, not hand-kept.** A script under `packages/client-core/scripts/`
(new) greps `packages/`, `plugins/`, and `apps/` for `name="..."`, `glyph: '...'`, and `icon: '...'`
literals whose values are Lucide names, writes `iconNodes.eager.json` (new) beside `iconNodes.ts`,
and fails if a literal in the tree is missing from the eager set. The check runs in `pnpm lint` for
client-core so a new literal icon cannot ship in the lazy half by accident.

**`Icon` renders in two steps.** With the eager map hit, it draws immediately. On a miss it renders
the `glyph` span fallback the kit already has and subscribes to the lazy map's promise; when the map
resolves it re-renders. The fallback is load-bearing for unknown names
([docs/ui-design.md](../../ui-design.md) § Icons), so a user-picked name renders as text for the
one frame before the map arrives unless the consumer awaited it. `IconPicker` and the task rail
await; the rest of the chrome only ever draws eager names and never sees the miss.

**The denylist is a name test, not a size test.** Names are what a person recognises in a build log,
and a chunk named `shiki` in a startup list is wrong whatever its size. The script reads
`__vite__mapDeps` in the entry chunk as well as the `modulepreload` links, because a chunk pulled by
a dynamic import's dependency list is also fetched at startup.

**The terminal client's check walks the static graph.** The TUI bundle has `modulePreload: false`
and one entry, so the analogue of the preload list is the static import closure of the chunk
`main.js` imports first. The script in this phase is the walk this read did by hand: regex the
import edges, follow them, sum the sizes. It is not exact (a re-export chain can be pruned by Node's
loader the same way it would not be), and exact is not needed to catch a 300 KB regression.

**Marks are printed, not stored.** No perf database, no dashboard. The node's marks are already
stderr lines; the helper's and the renderer's join them behind one variable; the terminal client's
are held and printed on exit. A developer reads a cold start as a dozen lines with a running offset.

## Tests

- `icon-census.mjs` fails when a literal icon name is added to the tree and not to the eager set.
- `Icon.test.tsx` (jsdom `hosts` project): an eager name renders an SVG synchronously; a lazy name
  renders the glyph fallback, then an SVG after the map resolves; an unknown name stays text.
- `check-renderer-budget.mjs` run against a fixture `index.html` that names a denylisted chunk
  fails with the chunk's name in the message.
- `check-startup-graph.mjs` run against a fixture `dist` with a known closure reports the known
  byte count.
- The node boot test and the TUI boot test (`apps/tui/src/node/boot.test.ts`) still pass; the marks
  are lines on stderr and must not change any protocol output.

## Done when

- `pnpm --filter @acorn/desktop build` passes its budget, and the icon chunk in the startup list is
  under 20 KB.
- Adding a static import of `DiffPane` to the shell entry fails the desktop build by name.
- `pnpm --filter @acorn/tui build` prints the eager closure's size and fails over the ceiling.
- A cold desktop start with `ACORN_PERF=1` prints a timeline spanning Rust's helper spawn, the
  helper's ready line, the node's `listener-up`, the renderer's first paint, and `nodeReady`, with
  offsets a person can subtract.
- `acorn` prints its own timeline on exit, ending in the first-draw time.
