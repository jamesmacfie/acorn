What this spike is showing

Sample change: the site's billing-api fixture. Everything here is fake data in one HTML file.

1 · A path, not a pile

The guide is a numbered path with an overview first and a wrap-up last. Each step says what you'll know after it (the goal), why the change exists, then the hunks. "Mark reviewed & continue" moves you on. j/k move between steps.

2 · Notes on lines

The agent leaves a few short notes pinned to lines: Explains (context), Look closely (a judgment call), and Risk (a likely bug). Each step's notes show as dots in the rail, so you can see where the risk is before you start. n jumps to the next note.

3 · Same diff, same ✦

The hunks are the diff kit's rows. Hover any line for the ✦ button, as in the pull request diff. A note is drawn in the inline agent card's shape, and Ask a follow-up turns it into that same conversation, anchored to the same line, so it shows in the Diff tab too.

4 · Notes reach the Diff tab

The guide also answers the code host's diff-line point, so its notes show as one-line marks under the rows in the full diff. A reviewer who skips the guide still sees them. The toggle hides them.

5 · Wrap-up turns notes into decisions

Every Look closely and Risk note becomes a checklist item at the end. The guide can't approve: it sends you to the pull request's own review controls.

6 · Narrow column

"Guide beside diff" is the review-panel column next to the diff. The rail folds into a stepper on top. Note links scroll the diff on the right.
