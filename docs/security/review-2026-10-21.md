# Acorn security review, October 21, 2026

A source review on October 21, 2026, against base commit `32b2ab6c3`, covered the work since
[the October 11 review](./review-2026-10-11.md): about 540 commits, including record triggers, row
actions, panel and app cards, supplied rows, code search, pairing by approval, and remote MCP sign-in.
It found one high, three medium, and two low problems. The review itself ran no attack against a
Node. The fixes were then checked live in `pnpm dev:agent` and on a standalone Node, as the
verification section says. The attacker throughout is the one [transport and auth](./transport-and-auth.md#why)
names: an agent that read hostile text and now acts for whoever wrote it, holding a task token. This
page records each finding, the change that closed it, and the verification.

## Findings

| ID | Area | Finding | Change | Status |
| --- | --- | --- | --- | --- |
| S1 | Plugin routes | A task token could post straight to a loaded plugin's agent tool handler, context section read, or CLI command route. That skipped the tool's risk tier, the owner's tool permissions, the signed ceiling, input checks, and the CLI command's device check. Severity: high. | The Node answers `404 not_found` to an internal caller on any path the host calls itself, and a device still passes. The set sits beside the route registry (`reserveHostDispatchedPath`), and every registration that names such a path reserves it. A reload or disable replaces the set. The recheck of every `dispatchPluginRoute` call added four paths the review's list missed: node actions, run sources, a code host's change request API, and data source discoveries ([the routes](./plugin-secrets-and-routes.md#routes-and-task-tokens)). | Fixed |
| S2 | Pairing | The **Allow a new client?** dialog swapped a newer request in place. An agent asking every three seconds could land its own request under the owner's click and collect a device token. Severity: medium. | An ask that lands while another is waiting cancels both and gets `409 pairing_busy`. The dialog never changes the request it shows: a frame that brings another request closes it and toasts. **Allow** is disabled for one second after the dialog opens. Asks have their own ceiling of 6 a minute, apart from codes ([pairing by approval](../api-reference/transport.md#pairing-by-approval)). | Fixed |
| S3 | Task creation | A task token could create a task in any project with a title, branch, and `origin` it chose. A record trigger on the Tasks source heard it within seconds and started a workflow. Severity: medium. | A task token creates tasks only in its own task's project, without `baseCommit` or `skipSetup`. The Node stores `origin` as `agent` and records the caller in the new `tasks.created_by_task_id` column. Core's Tasks source serves `createdByTask`, and the trigger approval sheet warns when a trigger would match agent-made tasks ([task creation](../workspaces-and-tasks/task-creation.md)). | Fixed |
| S4 | Triggers | A record trigger handed text that strangers wrote, such as a GitHub issue, to an unattended agent step. If the step's harness ran without asking permission, nothing stood between that text and a shell. Severity: medium. | A workflow session doesn't take the owner's session defaults, so a step's mode comes from its own options or the harness default. `agents.sessionExecute` refuses an autonomous turn in a listed unguarded mode unless the caller allows it. A record trigger allows it only when its approval ticked **Let agent steps run commands without asking**. The run fails with the cause `unguarded-agent`, and the trigger moves to **Needs review** ([triggers](../workflows/triggers.md)). | Fixed |
| S5 | Dependencies | `pnpm audit --prod` reported five advisories: Hono's `serveStatic`, and four in the public site's build. Severity: low. | Hono 4.13.11. Overrides move `source-map-js` to 1.2.2 and `postcss-selector-parser` to 7.1.6. The `braces` advisory, [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), has no fixed release, so it is ignored with a reason. | Fixed, one ignored |
| S6 | Plugin scaffold | The starter route in `create-acorn-plugin` loaded any task by ID, which taught authors a cross-task read. Severity: low. | The scaffold's `/greeting`, and `examples/plugins/hello-pane/server/routes.js` with it, hold a task-scoped caller to its own task. The comments on the example routes and the site pages say what the Node refuses. | Fixed |

The braces advisory is in the site build only (`starlight-llms-txt` through `micromatch`), with patterns
from the repository's own config. The `auditConfig.ignoreGhsas` entry in `pnpm-workspace.yaml` carries
that reason. Remove it, and take the release, once a fixed braces ships. The node-forge entry from the
October 11 review stays, because node-forge 1.4.0 is still the latest release and has no fix.

## Behavioral changes

- A task token gets `404 not_found` from a loaded plugin's agent tool handler, context section read,
  CLI command route, data source and discovery handler, schedule run, task check and cleanup route,
  hook handler route, harness probe, run list route, node action route, and a code host's change
  request API, over HTTP. The same paths still answer the host and a device. The path match decodes the
  URL and drops repeated and trailing slashes, so `/cli/%72aise` and `/cli/raise/` are refused too.
- A second pairing ask inside the time a first one waits cancels both and gets `409 pairing_busy`. The
  ask route has its own ceiling of 6 a minute, and the code route keeps its 20. The extension sidebar
  shows the message with a **Try again** button, the terminal client says to run `acorn` again or type a
  code, and the bridge answers `node.ask` with the new error code `pairing_busy`.
- **Allow** in the pairing dialog stays disabled for one second after the dialog opens. A frame that
  brings a different request closes the dialog and shows "Another pairing request arrived, so this one
  was cancelled."
- A task token creates tasks only in its own project, stored with `origin` set to `agent`, whatever the
  body says. A task token that names another project, sets `baseCommit`, or sets `skipSetup: true`
  gets `403 forbidden`, and so does a confined caller with no task ID. A device's request is unchanged.
  Migration `0014_hard_wild_pack.sql` adds the nullable `created_by_task_id` column.
- Core's Tasks source serves `createdByTask` on a task an agent made and leaves the field out of every
  other task. A record trigger on that source shows "Agents can create tasks this trigger would match"
  on its approval sheet unless its query has `createdByTask missing` in an `all` group.
- A record-triggered agent step in an unguarded mode stops at **Needs review** unless its trigger
  allows it. The step fails with the run's error cause `unguarded-agent`, naming the step and the mode.
  Clock triggers, **Run now**, manual runs, and agent launches behave as before. Saving a draft puts an
  approved trigger back in **Needs review**, so ticking the box needs approval again.
- The plugin scaffold's starter route answers `404` to an agent asking for a task other than its own.
- Hono is 4.13.11, and the Node service's size ceiling is 1,936,300 bytes.

### Attacks walked in a real session

A `pnpm dev:agent` session ran the Node and its window. A scratch plugin, `walk-probe`, was copied into
`dist/bundled-plugins`. It declares a harness whose command is a probe script, an agent tool, and a
CLI command. The Node started a real agent session on that harness, so the script held a task token
the Node had minted, and posted to the Node with it.

1. **A loaded plugin's CLI command route and tool handler.** `POST /v1/p/walk-probe/cli/ping`,
   `POST /v1/p/walk-probe/cli/%70ing`, and `POST /v1/p/walk-probe/tools/ping` each answered `404`. The
   same token got `200` for the plugin's tool through its own task's route, and the plugin's counter
   rose only for that call. From the owner's window, a device got `200` from both host-dispatched
   paths. Result: as expected.
2. **Pairing asks every three seconds.** The terminal client's ask showed its three words in the
   dialog. The attacker's first ask, three seconds into the loop, answered `409 pairing_busy`, closed
   the dialog, and made the terminal client's claim fail with `401 pairing_failed`. The attacker's
   second ask opened the dialog with the attacker's words, and its third ask closed it again. The
   owner's next ask opened the dialog with its own words, **Allow** worked after the one-second delay,
   and the claim returned a device token. Result: as expected, with two limits below.
3. **A task in another project.** `POST /v1/core/tasks` with the id of a project in a different
   workspace answered `403 forbidden`, with and without an `idempotency-key`. Result: as expected.

What the walk didn't show:

- The plugin was a scratch one, not `acme-alerts`, which phase 1 had checked on a standalone Node.
- The walk made no task in the agent's own project. That needs a branch in this repository, and the
  route test covers it.
- No record trigger was run end to end against an agent-made task.
- No real Claude Code or Codex session ran in a bypass mode, so S4 rests on the route and runner tests.
- The two limits in pairing: a loop of asks keeps the approval path from the owner. With four attacker
  asks, the last one stays held, so the owner's next ask also answered `409`. With five, the owner's
  next ask answered `429`, because the attacker had spent the 6 a minute. Pairing with a code is
  unaffected, because codes have their own ceiling.

## Decisions

- The Node service's size ceiling rose from 1,931,900 to 1,936,300 bytes on October 22, 2026, with the
  owner's approval, in `c32ae6b56`. Phases 1 to 5 grew the graph by 3,614 bytes, from 1,930,625 to
  1,934,239, and all of it runs at boot or on every plugin request, so none could move behind a dynamic
  import. The build leaves 2,061 bytes spare. The split by phase was 1,426 for the host-dispatched
  paths, 152 for pairing, 710 for task creation, 1,241 for unattended steps, and 85 for the Hono bump.
- `createdByTask` was added to the SDK's `sourceFields.json` in `bed7b2453`, which the
  `sourceFields.test.ts` architecture test needs after core's Tasks source gained the field.
- The fix for S1 closes only the paths the host dispatches. A blanket rule that refuses task tokens on
  every loaded plugin route is still a plugin contract change that needs its own design, as the
  October 11 review recorded. The rule covers fetch handlers, and compiled routers keep their per-route
  gates, which the mount coverage tests check.
- Task creation refusals for S3 are `403 forbidden`, as the existing `worktreePath` refusal is. No
  caller needed the old route: the CLI in a task terminal already refuses `task create`, and the
  workflows plugin creates tasks in process.
- For S4, the refusal can't happen when the step starts, because the mode is only known once its
  session exists. The trigger moves to **Needs review** when the failed run settles. Records already
  started in the same check can each fail once before it moves.
- R13 and R21 from the October 11 review stay open owner decisions. Agents can read the data root unless
  **Keep agents out of Acorn's data folder** is on, and an ad-hoc signed build keeps `data.key` in a
  plain file. S4 narrows what an unattended agent can do, and changes neither default.

### Still open

- `pnpm pack:node` fails on `ci-info`, on main as well. It needs the package list's owner.
- A path a source names in an answer, such as a row action's `runNodeAction` path or a writable
  field's `path`, isn't known when the source registers, so it stays open to internal callers. Its
  handler has to check the caller. A new kind of manifest route the host dispatches needs a line in
  `reserveManifestRoutes`, and a new registration that carries a path needs a `reserveDispatched` call
  at its context seam.
- A client whose own pairing ask was cancelled by someone else's overlap sees the ordinary
  denied-or-expired refusal on its next poll, with no **Try again**. The terminal client's new message
  (`packages/custody/src/local/pair.ts`) has no test of its own. A loop of asks can keep the owner's
  approval path busy for up to a minute, as the walk showed.
- Core's Tasks source offers no starter triggers, so none excludes agent-made tasks. A later starter
  should use `createdByTask` with `missing`. The warning checks only `all` groups, and `created_by_task_id`
  isn't on the wire `Task` type.
- If a refused agent step runs inside a child workflow, the run fails but the trigger doesn't move,
  because child runs don't pass their error cause up. A contributed agent kind gets no warning on the
  approval sheet, but the agents plugin still refuses it. The walk didn't run a real harness in each
  unguarded mode.
- `braces` and `node-forge` have no fixed release, so their audit entries stay until one ships.
- The October 11 page still says Hono 4.13.7 and one ignored advisory. It records that review's outcome.
