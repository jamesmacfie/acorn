# Acorn security review, November 20, 2026

A source review on November 20, 2026 looked for ways to run code on a user's Node without their
approval. It read Acorn at `90b9e61e3` and `acorn-cloud` at `19fa594`, and a second pass the same day
traced the account service's path to a Node at Acorn `31ff472da`. It found one critical, six high,
12 medium, 11 low, and one informational problem. The attacker is whoever holds the cloud account, the
account website, the hosted Slack gateway, or the relay, plus a loaded plugin or an agent that read
hostile text. Nothing ran against a live Node.

This page records the 24 findings with an Acorn fix. Each fix is one commit whose subject starts with
"Phase" and the finding's ID. Five of them still need `acorn-cloud` work, and their reports stay in
[the open findings](../future/security/README.md) with seven findings that are `acorn-cloud` only.

## Behavioral changes

- Migration `0001_link_confirmation` drops every Slack link and pending project pick, and ends every
  Slack thread. After upgrading, each owner confirms their Slack link once on a paired device.
- Slack turns refuse Codex and contributed harnesses. Acorn can't read Codex's approval policy, so it
  can't show that a Codex turn asks first.
- A phone runs nothing on the Node until a computer grants it shell access in **Settings → Nodes**.
  Without the grant, **Needs you** on the phone answers questions only, an agent in Auto takes no work
  from it, and the Database, API, Linear, and Rollbar panes are read-only there.
- No phone can sign the Node in or out, change remote access, previews, or connections, or change a
  Slack link, even with shell access.
- A laptop that a phone lets in gets a phone device. To give it full authority, revoke it and pair it
  again from a computer.
- Pairing with a Node an account lists shows identity words on both sides. Allow only when they match.
- **Phone previews** is off by default and separate from **Remote access**. Turning remote access off,
  or signing out, turns it off too. A Node with a hand-written relay turns previews on with
  `"previews": true` in `node.json`.
- Guests in a Slack channel reach the agent only after the owner runs `/acorn guests on` there.
- Agents can't pass a policy option such as `mode: 'auto'` to `agent_spawn`, and get `bad_request`.
  Auto for children comes from **Spawned agents** defaults or a parent already in Auto.
- A loaded plugin's new or moved project starts untrusted. Moving any project's folder resets trust,
  including the owner's own move in Settings.
- Loaded plugins that used one of the 10 private capabilities get `undefined` from `get`, or an init
  failure from `require`. `PLUGIN_API_MAJOR` didn't change.
- Remote previews need a matching desktop and Node. Either side older than this change fails to open
  one, which is the intended way to fail.
- Slack cards answered before G-1's migration have no row, so their buttons do nothing. Answer those in
  Acorn.
- Remote access refuses to turn on when the service names a `ws://` relay on another computer.
- Desktop builds outside a `v*` tag are unsigned for the updater. The macOS payload, `acorn.app.tar.gz`,
  comes from `apps/desktop/scripts/dist.mjs`, not Tauri.
- Standalone installs run `npm run build-native`, not `npm rebuild`, because the shipped `.npmrc` turns
  install scripts off.

## Verification

Each commit added the tests its finding asked for, and the completion notes say which fail on the old
code. Each fix also ran its package suites and the architecture tests. The release fixes have their own
architecture tests: `tools/arch/standaloneRelease.test.mjs`, `tools/arch/desktopSigning.test.mjs`, and
`tools/arch/relayImage.test.mjs`. D-3's cases are in `apps/desktop/scripts/node-runtime.test.mjs`.

These didn't run, so treat them as unchecked:

- No live walk with a paired phone, in `pnpm dev:agent` or `pnpm dev:remote`, for R-1, R-4, R-5, R-7,
  C-1, L-6, R-8, or R-9. The relay end-to-end tests cover the honest pairing and preview paths.
- L-2's read block wasn't checked with a real Claude Code session.
- No Slack workspace showed L-5's cards. Post one with `` echo <!here> *x* ``` <https://example.com|docs> ``
  and check it shows as typed.
- No workflow ran in GitHub Actions. The first `v*` tag is the first real run of `sign-desktop`.
- No Docker engine built the relay image with D-4's Dockerfile. Run
  `pnpm --filter @acorn/arch-tests exec vitest run relayImage.test.mjs`, the documented build, then
  `docker run --rm acorn-relay find /opt/acorn -name '.env*'`, which should print nothing.
- D-3 wasn't staged on Windows or Linux.

Together these fixes grew the Node service bundle by about 14 KB, to 1,972,303 B. The ceiling in
`apps/node/scripts/check-service-budget.mjs` went from 1,958,800 B to 1,974,300 B in `d8024e434`.

### acorn-cloud work

Each item has a report in [the open findings](../future/security/README.md):

- [G-1](../future/security/g-1-click-on-another-card-approves.md): route a card's clicks to the Node that
  posted it.
- [C-5](../future/security/c-5-sign-in-approval-shows-a-name-the-asker-chose.md): show the asker's
  address and the code's age, and shorten the refresh token for a sign-in with no Node.
- [R-6](../future/security/r-6-previews-put-the-cloud-inside-tls.md): refuse the preview DNS challenge
  unless the owner turned previews on, and say the service can read previews.
- [D-4](../future/security/d-4-relay-build-context-can-include-local-secret-files.md): build the relay
  from the resolved commit, and check images built from a working checkout.
- [R-7](../future/security/r-7-phone-rules-skip-plugin-routes-and-the-socket.md): ask for the account
  session on the Slack link page.
- C-2, C-3, C-4, G-3, G-4, G-5, and G-6 are `acorn-cloud` only and untouched.

The hosted service must keep doing four things, or Nodes refuse it. It signs owner assertions for
exactly `ASSERTION_LIFETIME_SECONDS`, and gateway tokens within `GATEWAY_TOKEN_LIFETIME_SECONDS`. It
names a `wss://` relay. It serves an `https` certificate authority directory on a public host whose
addresses stay on its own origin.

Optional hardening for `acorn-cloud`: sign each Slack delivery's sender, and tell a Node when its link
changes (X-1). Serve the phone app from a signed release the operator can't change (R-1, R-2). Give
relay credentials an expiry, then bind them to a Node key (L-2). Skip guest replies for a Node that
doesn't want them (S-1). Sign gateway tokens after the TLS handshake (S-5). Watch certificate logs for
preview certificates no Node ordered (R-6).

### Acorn follow-ups

- Slack turns on Codex need Acorn to set and read Codex's approval policy.
- An older client paired with an upgraded Node doesn't force `trusted: false` on a frame's project create.
- R-9 checks only literal addresses. A public name that resolves to a private address passes.
- `pnpm audit --prod` doesn't read the standalone npm lockfile, and the Dockerfile's base images are
  pinned by tag, not digest.
- `docs/future/node-tray/04-platform-archives.md` still describes the old `SHASUMS256.txt` check.
