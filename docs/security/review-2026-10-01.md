# Acorn security review — 30 September–1 October 2026

Review completed on 1 October 2026 against base commit `d3c89611ccfc1fb05a9db260821ee563315dba43`. Final verification is recorded below.

## Purpose and scope

Authorized defensive review of the owner’s open source Acorn application. Ten bespoke audit agents
ran sequentially, followed by sequential remediation agents. This review covers Acorn source and its
declared dependencies; it does not cover external applications.

## Reviewed areas

1. Authentication, pairing, and transport identity.
2. Task and resource authorization.
3. Loaded Node plugin isolation.
4. Plugin installation and package trust.
5. Managed agent and workflow authority.
6. Files, Git, repository trust, and task resources.
7. Network carriers and resource limits.
8. Secrets, logs, and backups.
9. Client plugin and desktop/TUI boundaries.
10. Runtime, dependencies, and CI supply chain.

## Dependency review

The initial npm audit returned 45 advisory records across 13 packages. Those records are not 45
independent application vulnerabilities. Production and development dependency reachability were
considered separately.

RustSec identified one vulnerability entry,
[RUSTSEC-2026-0285](https://rustsec.org/advisories/RUSTSEC-2026-0285.html). The compatible lockfile
patch changes rustls 0.23.43 to 0.23.45, including its registry checksum, without adding or removing
dependencies. The refreshed audit reports zero vulnerability entries and seven informational
warnings.

The shell calls `ureq` for development renderer proxying and entry-module readiness checks. Both use the configured `ACORN_DEV_SERVER` origin, whose launchers default to local HTTP. The environment variable can also be supplied to a packaged launch and is not restricted to HTTP. This review does not establish production TLS exposure or a completed attacker handshake.

The residual warnings include an unsound glib 0.18.5 string-array iterator in the Linux GTK graph
and six unmaintained dependencies. The macOS and Windows graphs do not contain that glib version.
Static review found no named affected API calls in Acorn or the 26 inspected reverse dependency
source roots outside glib's own code, documentation, and tests. That is not a complete reachability
proof, and Linux runtime verification was not performed.

The registry has no patched glib 0.18 release, and forcing glib 0.20 breaks the GTK type constraint.
Removing the five UNIC crates through tauri-utils 2.10 raises the minimum Rust version to 1.90,
beyond Acorn's declared 1.82. These require coordinated framework and platform work. No warning
suppression was added. The owning [Rust dependency security
section](../shell/packaging.md#rust-dependency-security) records the prerequisites and residual actions.

## Behavioral changes

- Device authorization now gates human approvals, managed session controls, workflow root starts, and GitHub import. Task reads and capability-driven trusted orchestration remain supported.
- Database requests validate all task IDs, browser captures validate their owning task, and memory queries stay within the task's project scope.
- Loaded handlers receive sanitized incoming headers. Native SQLite authorizers, module provenance, and shared builtin-family policy add defensive confinement controls. Loaded TUI workers receive an empty environment.
- Repository commands use the same captured bytes that were reviewed, and changed executable configuration requires renewed trust. Runtime URL discovery uses the captured active command.
- Filesystem consumers check canonical boundaries and regular descriptors. Docker task cleanup uses daemon working-directory association and full container IDs; it preserves volumes and networks.
- Browser diagnostics have byte and entry limits. Allocation is deduplicated and serialized, with failed context cleanup retained for retry before further allocation.
- The bundled Node runtime is 24.21.0. Supported secure floors are 22.23.2, 24.18.1, and 26.5.1; worker initialization enforces the shared policy.
- The npm dependency graph has targeted security patches, including smol-toml 1.7.1. Standalone packaging carries the tested runtime override policy.

- CI grants read-only repository tokens, disables persisted checkout credentials, and pins actions to verified upstream commits. Signing variables are limited to the key check and distribution step; distribution still runs trusted repository build code.
- The Rust lockfile patches rustls to 0.23.45. Seven informational RustSec warnings remain visible and require coordinated framework work.

- Plugin archives use one maintained parser and extractor over private immutable bytes. Expansion, logical size, metadata, file count, and depth have explicit limits. A supervised process has a heap cap and deadline. Opened package files must be regular and bounded; package fingerprints retain their format.
- Backup archives are created with mode 0600 inside private staging and replace the destination atomically only after successful completion. Failures preserve the prior archive.
- Event messages are capped at 8 MiB, incoming helper requests at 16 MiB, and preview messages at 64 KiB. Preview streams split ordered chunks with backpressure; HTTP responses retain their separate 64 MiB limit. Upgrade, handler, and closing-peer failures are contained.
- Pairing reads at most 4 KiB before parsing or consuming a code. Certificate discovery has an absolute eight-second deadline. Helper authentication compares UTF-8 byte lengths before its constant-time comparison.

- The Node logger scrubs and bounds tags, bodies, attribute keys, and values before stderr and collector emission. Direct collector records share attribute hygiene. Complete stderr lines retain at most 4,000 UTF-8 bytes. Pattern scrubbing recognizes known shapes and configured roots; it does not recognize arbitrary credentials.
- HTTP URL, scheme, and header preparation errors withhold resolved private fields. Command failures withhold raw diagnostics. Known private values are redacted from request and transport diagnostics in raw, URI-component, form, and lowercase forms. Chosen-endpoint response bodies and headers remain deliberate response data.

- Frame API, state, document, and webview handlers reserve request identities. Reusing a live ID closes the bridge before any reply or effect. Cancellation suppresses stale replies and aborts API signals; actual work retains its quota until settlement, even when an API ignores abort. Cancellation does not undo issued native effects.
- Remote trees validate every final descendant against the 64-level limit. Cleanup is iterative. Mounted update queues retain at most 4,000 operations and 1 MiB of UTF-8 JSON before appending. Overflow clears the queue and fails that mount once; remounting establishes fresh state.

## Remaining boundaries and limitations

- The application has one owner. Paired devices intentionally have owner authority; service principals remain unconfined for orchestration. Task credentials have narrower scope.
- Node worker permissions and plugin policy checks do not provide hostile-code operating-system isolation or process crash isolation. Explicit socket and execution grants remain powerful. In source development, harmless Hono source and metadata at sibling dependency symlinks remained readable despite individual-package launch grants; the bootstrap follow-up verifies explicit grant scope and refused imports, not complete filesystem confinement.
- Filesystem checks do not eliminate concurrent path replacement races or malicious Git metadata identity changes. Native SQLite opens remain separate from descriptor preflight.
- Three loaded-plugin candidates received defensive controls; no successful pre-fix escape was demonstrated.
- Synthetic tests use disposable fixtures. No real credential disclosure or destructive Docker testing was performed.
- Runtime verification uses Node 24.21.0 on macOS arm64. Node 22 and 26, Windows descriptor flags, and Windows access controls were not exercised. Loaded SQLite storage fails closed when its required native authorizer API is unavailable.
- Package limits do not turn linked local plugin folders into immutable snapshots. Concurrent replacement during later module imports remains possible. The archive meter bounds physical bytes, including metadata headers that the parser does not emit as entries.
- Browser allocation limits cover context count and retained diagnostic bytes. They do not impose operating-system limits on browser CPU, memory, screenshots, or outstanding host requests. Persistent native close failures remain a shutdown limitation.
- Docker working-directory metadata establishes the application's task association policy. It is not cryptographic proof of container ownership. Cleanup tests use mocked daemon responses and preserve networks and volumes.
- Frame work limits are per live bridge. Closing a bridge discards its accounting while native operations can remain pending; there is no global quota across remounts.
- The standalone manifest carries tested dependency floors and overrides. It does not ship an npm lockfile, so future npm resolution is not a byte-identical reproduction of the tested graph.

## Verification notes

- npm audit initially supplied an esbuild patch floor of 0.24.3, an unpublished version. The maintainer advisory specifies 0.25.0; the compatible tested override is 0.25.12.
- The installed standalone artifact used default npm peer resolution, without force or legacy-peer flags. Its actual launcher served an authenticated projects request from a fresh private root and shut down cleanly. Native PTY creation was verified separately through the checkout’s isolated driver.
- No hosted Actions execution, signed release, Linux GUI, Windows GUI, or native Docker cleanup ran. The artifact smoke disabled install scripts; native PTY acceptance used the checkout’s rebuilt native modules.
- Focused architecture and documentation checks are repeated gate runs, not independent test counts to sum into a total.
