This page lists the shortcuts acorn starts with, how to change them, what happens when two want the
same keys, and how focus decides where a key goes. Press <Keys chord="meta+/" /> anywhere for a sheet of
what the keyboard does right where you are.

## The defaults

These are the desktop defaults on macOS. On Windows, read Ctrl for ⌘. **Settings** > **General** >
**Keyboard shortcuts** lists every shortcut, including the ones plugins add, with what each is set to
now.

| Shortcut | What it does |
| --- | --- |
| <Keys chord="meta+k" /> | Open the command palette |
| <Keys chord="meta+/" /> | Show what the keyboard does here |
| <Keys chord="meta+," /> | Open Settings |
| <Keys chord="meta+l" /> | Switch project or workspace |
| <Keys chord="meta+;" /> | Switch to the last project or workspace |
| <Keys chord="meta+p" /> | Go to a file in this task |
| <Keys chord="meta+shift+n" /> | New task |
| <Keys chord="meta+1" /> to <Keys chord="meta+9" /> | Open the first nine tasks in the rail |
| <Keys chord="meta+0" /> | Open GitHub |
| <Keys chord="meta+shift+t" /> | Show or hide the terminal drawer |
| <Keys chord="meta+shift+enter" /> | Maximize the focused pane, or bring the row back |
| <Keys chord="meta+shift+f" /> | Find in files |

Each pane has its own shortcut to show it:

| Shortcut | Pane |
| --- | --- |
| <Keys chord="meta+shift+r" /> | Pull request |
| <Keys chord="meta+shift+a" /> | Agent |
| <Keys chord="meta+shift+g" /> | Git |
| <Keys chord="meta+shift+d" /> | Notes |
| <Keys chord="meta+shift+x" /> | Context |
| <Keys chord="meta+shift+e" /> | Editor |
| <Keys chord="meta+shift+b" /> | Preview |
| <Keys chord="meta+shift+j" /> | Database |
| <Keys chord="meta+shift+h" /> | API |

Inside a pane, a few more apply. <Keys chord="meta+enter" /> commits in the Changes tab's message box
and runs the query in the Database pane. In a pull request's list, `/` finds a file, `]` and `[` move
between changed files, and `c` creates a pull request.

## Change a shortcut

1. Open **Settings** > **General** > **Keyboard shortcuts**.
2. Click the shortcut you want to change, and press the new keys. Esc or Tab leaves it as it was.
3. To remove a shortcut, click the unbind button beside it. To go back to the defaults for a group,
   click **Reset section**.

If the keys you press are already in use, acorn refuses them and says what uses them. Your changes are
saved on this device. Removing a plugin keeps your changes to its shortcuts, so reinstalling it brings
them back.

## When two shortcuts want the same keys

- A shortcut you set beats any default.
- Among defaults, acorn's own win, then plugins' in the order they were installed.
- The losing default gets no keys at all. Settings shows it beside the one that won, with **Also used
  by**. acorn never picks other keys for it.

One overlap is on purpose. A pane's shortcut and a task's shortcut can share keys, and the pane with
focus wins. <Keys chord="meta+shift+t" /> reopens a closed file while the Editor has focus, and shows
the terminal drawer anywhere else.

A plugin can't take <Keys chord="meta+k" />, <Keys chord="meta+," />, <Keys chord="meta+1" /> to
<Keys chord="meta+9" />, or Esc.

## Where a key goes

- **While you type in a field**, a key without ⌘, Ctrl, or Option goes to the field. Shortcuts with
  one of those still work, so <Keys chord="meta+enter" /> commits from the message box.
- **Inside a pane**, F6 and Shift+F6 move between its regions, such as a list and its detail. Ctrl+Option
  with Left or Right moves between panes. Each region remembers where you were, so coming back lands in
  the same place.
- **In a list**, the arrow keys, Home, End, and Page Up and Page Down move, and typing jumps to a
  matching row.
- **Settings** covers the window, so no task or pane shortcut acts while it's open.

### What Esc does

Esc closes the thing on top, one at a time: a menu, then a dialog, then the palette. In the palette, it
goes back one step first. With nothing open, Esc brings back the pane row after you've maximized a
pane. A plugin can't claim Esc for itself.

## In the terminal

The terminal client uses the same shortcuts with Ctrl in place of ⌘, because a terminal never passes ⌘
through. <Keys chord="ctrl+k" /> opens the palette. The footer line always lists what the keys do where
you are, and `?` opens the full sheet. Tab and Shift+Tab move between regions, beside F6. Keys without
a modifier also work outside a text field: `w`, `p`, `;`, `/`, `n`, `t`, and `q`. [Desktop and
terminal](/docs/start/desktop-and-terminal/#keys-in-the-terminal-client) lists them. To change a
shortcut, use the desktop app.

## Limits

- Some keys never reach acorn, because the operating system or the terminal keeps them.
- A shortcut that lost a conflict has no keys until you give it some.
