You'll draw a pane whose pixels are yours: a sandboxed frame with your own DOM, here a canvas chart.
Use a frame only for what acorn's components can't draw. Anything else is a tree.

## The result

The Acme frame example's **Deploy chart** pane draws a line chart on a canvas, in the theme's accent
color. There's no picture here: the site draws trees, and a frame is your own code running. In the
terminal client, the pane is one muted line that names the plugin and points at the desktop app.

## Before you start

Scaffold with `npm create acorn-plugin acme-frame -- --rectangle`, which writes a frame instead of a
tree, and install it as in [Build your first plugin](/docs/build-plugins/start/build-your-first-plugin/).
The code is from [`examples/plugins/acme-frame`](https://github.com/jamesmacfie/acorn/tree/main/examples/plugins/acme-frame).

## What the sandbox allows

The frame runs at its own origin, `app-plugin://<hash>`, with no network: `fetch`, WebSockets, and the
like all fail. It can load only `client.js` and acorn's `/ui.css`, so inline anything else. `alert` and
`confirm` are suppressed, and the clipboard and links go through the bridge: `ui.copy`, and `ui.openUrl`
for `https` addresses, only while the frame has focus.

The bridge closes and shows a placeholder after 100 requests in flight, or 1,000 messages in 10
seconds.

## Mistakes

- Sending nothing back on `ready`. Any message counts, and `{ kind: 'connected' }` is the usual one.
- Hard-coding colors. Read the theme's custom properties, or the frame looks wrong in every other theme.
- Claiming `meta+k`, `meta+,`, `meta+1` to `meta+9`, or Escape. They're never a plugin's.

## In the terminal

A frame draws as one muted line naming your plugin. Put anything the terminal needs in a tree.

## Limits

- A frame is for a pane, a panel, a settings page, an overlay, or another plugin's `rectangle` point.
  Small surfaces such as badges never take one.
- One client bundle per plugin: a frame and your trees share `client.js`.
