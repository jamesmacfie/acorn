You'll add a command people and scripts can run with `acorn plugin <your id> <command>`, answered by
your Node half, with its input and output checked against schemas you declare.

## The result

```text
$ acorn plugin acme-data deploys --input-file task.json --output json
{"pluginId":"acme-data","command":"deploys","result":{"deploys":[{"environment":"staging","status":"succeeded","sha":"a1b2c3d","at":1792195200000}]}}
```

`task.json` holds `{ "nodeId": "…", "taskId": "…" }`. `acorn plugin acme-data commands` lists the
command, and `--help` after it prints its title, summary, scope, and both schemas.

## Before you start

Read [Store data](/docs/build-plugins/node/store-data/). The code is from
[`examples/plugins/acme-data`](https://github.com/jamesmacfie/acorn/tree/main/examples/plugins/acme-data).

## Commands that write

Set `risk` to `write` and say what changes in `effects`, which `--help` prints. Each run then carries an
idempotency key: the command line makes one, or takes `--request-id` for a retry, and the Node replays
the first answer to a retry with the same key and input, so your route runs once.

```json manifest title="acorn-plugin.json"
{
  "node": "./node/index.js",
  "permissions": { "node": { "core": ["tasks"] } },
  "contributions": {
    "cliCommands": [{
      "name": "record", "title": "Record a deploy", "summary": "Record a deploy of a task's commit.",
      "effects": "Adds a deploy to the task's history.", "risk": "write", "scope": "task", "capability": "tasks",
      "route": { "method": "POST", "path": "/cli/record" },
      "inputSchema": { "type": "object", "properties": { "nodeId": { "type": "string" },
        "taskId": { "type": "string" }, "sha": { "type": "string" } },
        "required": ["nodeId", "taskId", "sha"], "additionalProperties": false },
      "outputSchema": { "type": "object", "properties": { "deployId": { "type": "string" } },
        "required": ["deployId"], "additionalProperties": false }
    }]
  }
}
```

Don't offer anything destructive this way. A command has no confirmation.

## Mistakes

- A route that doesn't exist. The manifest can't prove your handler serves `/cli/<name>`, so it fails
  when someone runs it. Run it once before you ship.
- An answer that doesn't fit `outputSchema`. The Node refuses it rather than printing it.
- Changing what an input means and keeping the name. A script that worked keeps running, and does the
  wrong thing. Add a new command instead.

A write command says what it changes:

```json manifest-invalid title="Wrong: acorn-plugin.json"
{
  "node": "./node/index.js",
  "permissions": { "node": { "core": ["tasks"] } },
  "contributions": {
    "cliCommands": [{
      "name": "prune", "title": "Prune deploys", "summary": "Remove old deploys.", "risk": "write",
      "scope": "node", "capability": "tasks", "route": { "method": "POST", "path": "/cli/prune" },
      "inputSchema": { "type": "object", "properties": { "nodeId": { "type": "string" } }, "required": ["nodeId"] },
      "outputSchema": { "type": "object", "properties": {} }
    }]
  }
}
```

```json manifest title="Right: acorn-plugin.json"
{
  "node": "./node/index.js",
  "permissions": { "node": { "core": ["tasks"] } },
  "contributions": {
    "cliCommands": [{
      "name": "prune", "title": "Prune deploys", "summary": "Remove old deploys.", "risk": "write",
      "effects": "Deletes deploys older than 30 days.",
      "scope": "node", "capability": "tasks", "route": { "method": "POST", "path": "/cli/prune" },
      "inputSchema": { "type": "object", "properties": { "nodeId": { "type": "string" } }, "required": ["nodeId"] },
      "outputSchema": { "type": "object", "properties": {} }
    }]
  }
}
```

## In the terminal

This is the command line, not the terminal client: `acorn` with a subcommand, for scripts and agents.
It talks to whichever Node you choose with `--node`.

## Limits

- Up to 16 commands per plugin.
- An input is at most 64 KiB, and an answer at most 256 KiB.
- A command never receives the device's token in its input.
