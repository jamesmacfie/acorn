You'll make your Node half hear what happens in acorn, tell other plugins when your data changes, and
offer other plugins a function to call.

## The result

Two example plugins work together without importing each other. acme-data records a pending staging
deploy whenever a commit lands on a task's branch, and announces it. acme-tracker hears that, and its
mark on the task row gains the deploy, such as **2 Acme issue(s), staging deploy pending**.

## Before you start

Read [Write the Node half](/docs/build-plugins/node/write-the-node-half/). The code is from
[`examples/plugins/acme-data`](https://github.com/jamesmacfie/acorn/tree/main/examples/plugins/acme-data)
and [`examples/plugins/acme-tracker`](https://github.com/jamesmacfie/acorn/tree/main/examples/plugins/acme-tracker).

## Choose one

- An **event** says "this changed, read it again". It carries a little state, fans out to whoever
  listens, and waits for nobody.
- A **capability** answers a question: a function another plugin calls and gets a result from.

## Events have no replay

An event is sent once, to whoever is listening at that moment. Nothing stores it. A listener that
starts late, restarts, or loses its connection misses what happened in between. So:

- Never keep state you only learn from events. Read it from its owner when you start, and again when
  an event says it changed.
- Never use an event as a job queue. Write the job to your database, and use the event to say "look".
- Make a payload state, such as "the branch is at `f00dfeed`", not a step, such as "one more commit".
  A missed frame then heals on the next one.

## Mistakes

- Listening to a core event you didn't name in `permissions.events`. `on` throws, so you find out at
  start.
- Sending on another plugin's channel, or on core's. `send` throws: a plugin you install may only send
  on its own `plugin:<id>:` channel.
- Listening to a verb the other plugin doesn't list in `emits`. When that plugin is running, `on`
  throws. When it isn't, you hear nothing, with no error.
- Importing another plugin's code or opening its database. Neither works from your worker. Use its
  capability.

A verb in `emits` is a short word, not a channel:

```json manifest-invalid title="Wrong: acorn-plugin.json"
{
  "emits": [{ "verb": "plugin:acme:deploys-changed", "description": "A deploy changed" }]
}
```

```json manifest title="Right: acorn-plugin.json"
{
  "emits": [{ "verb": "deploys-changed", "description": "A deploy changed" }]
}
```

## In the terminal

Events and capabilities live on the Node, so the terminal client sees their effects the same way.

## Limits

- Core publishes 13 events, from `plugins:changed` to `data-source:changed`.
  [Permissions](/docs/build-plugins/reference/permissions/) lists them under **Event channels**.
- Some things are never events: file saves, terminal output, keystrokes, and request bodies. A plugin
  that wants file changes watches files on its Node half.
- A capability call crosses from one plugin's worker to another's, so pass and return plain data.
