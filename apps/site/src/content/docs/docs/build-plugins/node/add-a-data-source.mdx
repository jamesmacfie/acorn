You'll make your plugin's records something a dashboard panel can show and a workflow can read: a
typed data source, answered by your Node half.

## The result

**Acme deploys** is a source under **Add panel** > **Start from data**, with a starter panel,
**Deploys by environment**, that counts deploys per environment. A workflow's **Find records** step
can read it too. **Acme release readiness**, a derived source, shows each task and how far its work
has shipped, built from acorn's tasks and acme-data's deploys.

## Before you start

Read [Store data](/docs/build-plugins/node/store-data/). The code is from
[`examples/plugins/acme-data`](https://github.com/jamesmacfie/acorn/tree/main/examples/plugins/acme-data)
and [`examples/plugins/acme-readiness`](https://github.com/jamesmacfie/acorn/tree/main/examples/plugins/acme-readiness).

## Choose one

- A **typed source** serves records you have: your own table, or a service's API. You describe the
  fields and answer each read.
- A **derived source** builds records from sources acorn already reads, such as tasks and pull
  requests. The SDK answers the reads, and acorn reads the inputs with the person's accounts, so your
  code never sees a credential.

1. **Declare it.** The handler is one route, and every operation posts to it.

2. **Describe the records.** `describe` answers the record's JSON schema and what each field means:

   <ExampleCode file="acme-data/server/source.js" region="describe" />

   - `origin: "declared"` is a field every record has. `display` says how to show it, and `role` marks
     the title, status, and when it changed.
   - `choices` lists a field's values, each with a `tone` and a `rank` that columns inherit.
   - `query` on a field lists the operators your handler applies, such as `eq`, and whether it can
     sort. Leave it out and acorn never sends a filter you'd have to apply. Dashboards still filter and
     group the rows they read.

     are.

   with the next cursor until the last page, which is `complete`:

   <ExampleCode file="acme-data/server/source.js" region="query" />

## Identity, reach, and coverage

- **Identity.** A source with a `providerId` reads one of the person's connections per panel. Declare
  an `identity` operation, and acorn asks your route who the account is, so a panel can filter on
  **You**.
- **Reach.** A source that maps records to projects with `projectScope` is limited to the projects the
  workspace links, and each record gets its project.
- **Coverage.** Say whether you serve a `snapshot`, what's true now, or `events`, a history with a
  retention. A dashboard warns when a time window reaches before what you cover.
- **Discovery.** A plugin whose sources depend on the account, such as one per board, adds
  `dataSourceDiscoveries`, and a discovery route lists them, up to 100 a page.

## Mistakes

- Advertising an operator you don't apply. acorn trusts the field's `query`, and never filters behind
  your back.
- A record id that changes between reads. Panels and details find a record by it.
- Returning the same record twice across pages, or the same cursor twice. acorn refuses the read.
- Answering `incomplete` before the last page. acorn stops at the first page that isn't `more`, so a
  read you cut answers `more` until its last page, and says it's `incomplete` there.
- A record over 256 KiB. It fails rather than being cut.

A derived source's inputs must be other plugins' sources, named `<pluginId>:<sourceId>`:

```json manifest-invalid title="Wrong: acorn-plugin.json"
{
  "node": "./dist/node.js",
  "contributions": {
    "dataSources": [{ "sourceId": "readiness", "name": "Readiness", "singular": "Task", "plural": "Tasks",
      "identityScope": "Built from its inputs", "handler": "/v1/p/acme/source",
      "inputs": { "tasks": { "source": "tasks", "label": "Tasks" } } }]
  }
}
```

```json manifest title="Right: acorn-plugin.json"
{
  "node": "./dist/node.js",
  "contributions": {
    "dataSources": [{ "sourceId": "readiness", "name": "Readiness", "singular": "Task", "plural": "Tasks",
      "identityScope": "Built from its inputs", "handler": "/v1/p/acme/source",
      "inputs": { "tasks": { "source": "core:tasks", "label": "Tasks" } } }]
  }
}
```

## In the terminal

The terminal client doesn't draw dashboards. A workflow that reads your source runs on the Node, so it
works whichever app started it.

## Limits

- Up to 32 sources and 8 discoveries per plugin, 10 starter panels per source, and 8 inputs per derived
  source.
- A read is at most 100 pages, 5,000 records, 16 MiB, and 60 seconds. A preview is one page of 25.
- A derived source can't write through its inputs, and its `actions` are always empty.
