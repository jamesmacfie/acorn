You'll have your plugin write something with an AI model, such as a summary, using the model the
person chose for your plugin. Your plugin never sees a key and never picks what to spend.

## The result

Right-click a task row and pick **Summarize Acme notes**. A moment later the bell has a row,
**Acme notes summarized**, with two sentences the model wrote from the task's notes, and the summary is
saved as a note an agent can read.

On the plugin's page in **Settings** > **Plugins**, a **Model** section holds what it may spend:

| Row | What it sets |
| --- | --- |
| **Generate with** | The backend and model your plugin's calls use: an API key the person connected, or an agent command line on the Node's computer |
| **Daily allowance** | Output tokens per day, with **Save** and **Remove** |
| **Today** | How much of the allowance today's calls used |

## Before you start

Read [Write the Node half](/docs/build-plugins/node/write-the-node-half/). The code is from
[`examples/plugins/acme-agent`](https://github.com/jamesmacfie/acorn/tree/main/examples/plugins/acme-agent).

## Which model runs

| What the person has | What your call spends |
| --- | --- |
| A grant on your plugin's page | That backend and model, within the allowance |
| No grant | Nothing. The call fails with `provider_not_configured`, and acorn never picks one for you |
| An API key | The key's provider, such as Anthropic or OpenAI, and the model they picked |
| No key, but Claude Code or Codex installed | That command line, run once with its tools off, in an empty folder, with its own login |

**Generate with** under **Agents** > **Harnesses and defaults** is the person's default for acorn's
own Generate controls, such as the commit message. Your plugin has its own **Generate with**, on its
page, so the two never get in each other's way.

A command line can't be held to a token count, so each call to one counts as 4,000 output tokens
against the allowance, whatever it reports.

## Mistakes

- Naming a `backendId` yourself, such as the first one `available()` lists. It runs, but outside the
  allowance, and the person's page says your plugin did it.
- Passing `input.modelId`. The person chose the model, so a different one is refused.
- Retrying a failed call. A timeout or a cancelled call stays charged, because the provider may already
  have spent it.
- Generating on every request, such as every time a pane opens. Generate when the person asks, and save
  the answer.
- Misspelling a facet, such as `model` for `models`. acorn skips a facet it doesn't know rather than
  refusing the manifest, so `ctx.core.models` is missing and your first call throws a `TypeError`.

## In the terminal

The grant lives on the Node, so a call from your plugin works the same whichever app the person uses.
The plugin's page, where they set it, opens in the desktop app.

## Limits

- A system prompt is at most 100,000 characters, a prompt 1,000,000, and an answer 128,000 output
  tokens. A call has at most three minutes.
- The allowance resets at midnight on the Node's clock.
- acorn stores no prompt and no answer, and sends neither to telemetry.
