You'll add a view of the page's task to the browser extension's panel, such as the state of the app
the task runs and links into it, answered as JSON by your Node half.

## The result

On a page that belongs to a task with the Acme app running, the task's tabs in the panel gain **Acme app**:

<SidebarPicture id="sidebar-plugin-panel" />

**Open in Acorn** opens the task in the desktop app. **Refresh** reads the panel again.

## Before you start

Read [Write the Node half](/docs/build-plugins/node/write-the-node-half/), and
[Match your app's pages to tasks](/docs/build-plugins/node/match-your-apps-pages-to-tasks/) if your
panel is about an app the task runs. The code is from
[`examples/plugins/acme-browser`](https://github.com/jamesmacfie/acorn/tree/main/examples/plugins/acme-browser).

## The blocks

| Block | Fields |
| --- | --- |
| `status` | `label`, `state`, `severity`, and an optional `detail`, drawn as preformatted text |
| `links` | `title`, and up to 16 `{ label, url }`, each with an optional `ready` |
| `rows` | `title`, and up to 64 `{ label, state, severity }` |
| `logs` | `title`, up to 32 `sources`, the `source` shown or `null`, and up to 200 `lines` |

`severity` is `info`, `warn`, `danger`, or `pending` for a state on its way to healthy. The extension
opens an `http` or `https` link in a new tab and offers every link to copy, so a database address is
still useful. `ready: false` shows a link that isn't answering yet without opening it. When the person
picks a log source, the extension adds `&source=<id>` to the read.

Everything is drawn as plain text, never as markup.

## Mistakes

- Putting a button in the panel. It's read-only by design: anything that changes state, such as
  restarting a service, belongs in your pane in the desktop app, which **Open in Acorn** reaches.
- A slow route. Every read runs it, while the person waits.
- A block kind or field acorn doesn't know. The whole view is refused, the panel shows an error, and it
  keeps the last view it had.
- Answering a caller whose credential is bound to one task. The extension calls with the device's.

`pane` names one of your own task panes, so a panel with no client can't name one:

```json manifest-invalid title="Wrong: acorn-plugin.json"
{
  "node": "./node.js",
  "contributions": {
    "browserPanel": { "label": "Acme app", "pane": "acme-app", "route": "/v1/p/acme/browser-panel" }
  }
}
```

```json manifest title="Right: acorn-plugin.json"
{
  "node": "./node.js",
  "contributions": {
    "browserPanel": { "label": "Acme app", "route": "/v1/p/acme/browser-panel" }
  }
}
```

## In the terminal

This is a browser extension feature. The desktop pane that **Open in Acorn** opens draws in the
terminal client too.

## Limits

- One panel per plugin, and 12 blocks per view.
- Labels, titles, and states are 1 to 40 characters, and a row's label up to 80. A `detail` is at most
  2,000 characters, and a log line 1,000. A view is at most 512 KiB.
