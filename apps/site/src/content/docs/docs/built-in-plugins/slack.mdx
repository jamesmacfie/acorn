The Slack plugin starts an agent on your Node when you mention @acorn in a Slack channel or send it a
DM. The agent's progress, its permission requests, and its answer come back to the same thread. Your
Node never holds a Slack token: the account service's Slack gateway makes each Slack call for it.

## Link Slack

Open **Settings** > **Connections** > **Slack** and click **Link Slack**. Open the address it shows and
sign in with Slack. The page finds the link once it reaches your Node, and shows the workspace and the
Slack user it names. Click **Confirm** if that's you, or **Not me, unlink** if it isn't. Slack can't
start anything on your Node until you confirm. If the link later names a different Slack user, you
confirm again. Only your own Slack user starts turns on your Node. By default the agent reads nothing
anyone else writes in your thread.

Every command an agent runs from Slack waits for your approval. A Claude Code session switches to
**Default** mode, even if you usually run it in **Auto**. Codex can't start from Slack, because acorn
can't confirm that it asks before each command.

**Answer approvals from Slack** sits beside **Confirm** and is off unless you tick it. With it on, a
request to run a command shows **Approve** and **Deny** in the thread. With it off, the card links to the
task in acorn instead. If the hosted service were broken into, whoever did it could send your agent a
prompt, and with the switch on, approve what it runs.

## Use it

- **Mention @acorn** in a channel the bot is in. In a channel, each mention starts a task of its own,
  with a branch. Reply in the thread to send the agent more.
- **DM the bot.** Each DM starts a separate conversation in one task for the project, with no branch.
- **`/acorn project <name>`** sets the project for the channel or DM. With none set, the bot asks you
  to pick one.
- **`/acorn mode tasks`** or **`/acorn mode conversation`** chooses how new threads work there.
- **`/acorn guests on`** lets the agent read other people's replies in its threads there, and the
  thread's earlier messages when you mention it partway through. It reads them as untrusted, by Slack
  user ID, and every command still waits for your approval. Anyone who can post in the channel can
  write that text, Slack Connect guests included, so turn it on only where you trust them.
  **`/acorn guests off`** turns it off again.

A reaction on your message shows where the turn is: 👀 received, ⏳ working, ✋ waiting for you, ✅ done,
❌ failed. A status line in the thread names what the agent is doing, and the answer posts as a reply of
its own. Turns you type in acorn for that session post to the thread too.

Archive the task, or the session in a conversation, and the thread ends. Mention @acorn there to start
again. If your Node is off, Slack tells you so, and nothing is kept for later.
