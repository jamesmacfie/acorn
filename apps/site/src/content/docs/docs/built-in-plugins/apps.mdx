The Apps plugin lets an agent answer with a small app in the conversation: a list you can narrow, a form
that fills in a message, a checklist, or rows with a button that asks the agent about each one. An app
reads your data through the same plans a dashboard panel uses, and the agent's view of one chart or table
stays a panel.

## Build an app

There's nothing to set up.

<Steps>

1. In a task's managed agent session, ask for something one chart can't show, such as "my tasks grouped
   by status, with a tick to mark each one reviewed and a button that asks you what's left on it".

   <Checkpoint>The agent reads the app guide, builds the app, and a card draws it below the agent's
   message.</Checkpoint>

2. Ask for a change, such as "only show active tasks".

   <Checkpoint>A second card draws the new version. The first collapses to one line, such as "v1: Tasks
   grouped by status. Replaced by v2."</Checkpoint>

</Steps>

## Open and edit an app

Once an agent shows an app in a task, the task gets an **Apps** pane.

<Steps>

1. Select **Open** on the app's card.

   <Checkpoint>The Apps pane lists the task's apps and draws the one you opened at full size.</Checkpoint>

2. Select **Edit with agent**, and ask for a change in the conversation that opens under the app.

   <Checkpoint>It's the same conversation as in the Agent pane. When the agent shows the change, the
   pane draws the new version.</Checkpoint>

</Steps>

If the session that built the app is archived, **Edit with agent** offers **Start an editing
session**. The new session's first message carries the app, so you don't have to say which one you
mean.

## Share an app with the project

An app you want to keep past its task can belong to the project instead.

<Steps>

1. Select **Publish to project** on the app's card or in the Apps pane.

   <Checkpoint>An **Apps** source appears in the left rail. It lists the project's apps, and selecting
   one draws it at full size.</Checkpoint>

2. Ask the agent in the same task for a change, then select **Publish** in the Apps pane.

   <Checkpoint>The project's app shows the change. Ticks you made in it stay.</Checkpoint>

</Steps>

To change a project app later, open it from **Apps** and select **Edit in a new task**, or **Edit in
this task** when the task you were in belongs to the same project. The task gets a draft of the app
and, for a new task, an agent session that already has the app. If someone published the app after
your draft started, **Publish** asks whether to publish your draft as a new app or replace theirs.

**Delete** moves a project app to **Archived apps** at the bottom of the list, where **Restore** brings it
back and **Remove for good** deletes it. When you archive a task whose app has changes the project
doesn't have, the archive dialog offers to publish them first.

## Put an app on a dashboard

A project app can sit on a Home tab beside your panels. Select **Add to dashboard** on the app in
**Apps**, or in its row's **…** menu, and pick a tab of the workspace that holds the project. On an
app's card in the chat, **Publish and add to dashboard** publishes it to the project first.

On Home, the app shows its project's name and its latest version, and keeps the same ticks as in
**Apps**. It reads its data again when the window comes back into focus, and on each plan's refresh
interval, as panels do. Its menu has **Open app**, **Edit in a new task**, and **Remove from this
dashboard**. If you delete the app, its place on Home says so and offers **Restore**.

## Turn an app into a plugin

When an app needs more than an app can do, such as settings, its own data, or a service of its own, an
agent can rebuild it as an ordinary plugin.

<Steps>

1. Open the app in **Apps** and select **Turn into a plugin**. Give the plugin an ID and a name, and
   choose a new folder for it.

   <Checkpoint>The folder holds a plugin package. Its manifest lists the plugins behind the app's data
   as plugins it requires. A new task opens with an agent session that has the app attached.</Checkpoint>

2. Send a message, such as "go ahead". The agent can't see the app, so paste a screenshot of it too.

   <Checkpoint>The agent rebuilds the app as the plugin's pane, over the same data.</Checkpoint>

3. Install the folder when the agent asks, or from **Settings › Plugins › Install… › Local folder**.

   <Checkpoint>Acorn asks you to approve the plugin, listing what it reads and adds. Its pane then
   shows what the app showed.</Checkpoint>

</Steps>

The app doesn't change, and it stays until you delete it. What the app had ticked or typed is in the
folder as `app-state.seed.json`. The plugin doesn't read it unless you ask the agent to load it.

## Earlier versions

Only the newest card is live. An older card's line offers two buttons:

- **Show** draws that version read only, with today's data.
- **Restore** makes that version the newest again, as the next version, and the card you pressed draws
  it.

## What an app can do

An app arranges Acorn's own components and panels. Nothing an agent writes runs as code, so an app needs
no trust prompt. An app can:

- Read the plans it was built with, under your account, the way a dashboard panel does.
- Put text in the agent's message box. It never sends a message. You send, edit, or delete it.
- Open a web link, after you confirm the full address. It can't open a file or any other kind of link.
- Run an action a data source offers on one of its rows, after you confirm it.

An app can't reach the network, read a secret, or start a program.

## Limits

- An app remembers what you tick or type, up to 256 KiB, after a reload or a restart. When the agent
  changes the app, it keeps what you set as long as the agent keeps the names it stores it under.
- An app belongs to the task it was built in until you publish it. Archiving the task keeps it, and the
  archive dialog says so. While the task is archived, its preview lists the app's versions and doesn't
  run them. Restoring the task brings the app back. Deleting the task deletes it, and leaves the
  project's copy.
- A project app has no task, so it can't ask the agent anything or read which task it's in. Edit it in
  a task to do either.

## In the terminal

The terminal client draws an app's text, buttons, and fields with its own components, in a card up to 24
rows tall or in the Apps pane. A chart or table inside an app draws as one line, as a dashboard panel card does. A link's
confirm copies the address instead of opening it.
