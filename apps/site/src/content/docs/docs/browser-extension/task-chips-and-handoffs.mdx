On a site a plugin knows, such as GitHub, the extension draws a small chip on the page. On a page that
belongs to a task, the chip names the task. On an item no task holds yet, it offers to start one. This
page covers the chip, the handoff card in the panel, and how a page is matched to its task.

## Which sites get a chip

A plugin on your Node says which pages it can bring into a task, and where on the page to put the chip.
The desktop app's Node has GitHub, Linear, and Rollbar. A standalone Node has GitHub, and Linear and
Rollbar once you install them.

A page gets its chip once the extension can read it: turn on its site's switch under **Settings** >
**Sites** in the panel, or click the Acorn toolbar button on that tab. Without either, the panel
still offers the same handoff in **This page**.

## The task chip

On a page that belongs to a task, the chip shows the task's name and its agents, such as **2 working**,
or **1 waiting** when an agent waits on you. Click it to open the panel on that task. The arrow beside
it opens a menu:

- **Show in side panel** opens the panel on the task.
- **New chat about this page** opens the task's **Agents** tab, with the page's link waiting for the next
  conversation.
- **Ask about an element** lets you point at part of the page and ask the task's agent
  ([Ask about an element](/docs/browser-extension/ask-about-an-element/)).
- **Open in Acorn** opens the task in the desktop app, on the pane that shows the item.
- **Copy Acorn link** copies a link to the task.

The chip draws in its own sealed box, so the page can't restyle it or read it, and it follows the page's
light or dark theme.

## Bring an item into a task

On a page no task holds, such as a pull request you haven't started on, the chip reads **Start task**.
Its menu has **Create task** and **Run workflow…**, the handoff card's two actions. Either opens the
panel on the handoff card, which Home also shows on its own for a page no task holds. **Run workflow…**
opens the card with its list of workflows open.

<SidebarPicture id="sidebar-handoff" />

The card shows the item the page is, as the plugin reads it: its key, the connection, and its title,
with an arrow that opens the item in the desktop app.

1. If the page is more than one item, such as one per GitHub account, pick one from the key's list.
2. A task that already holds the item shows as its row. Click it to open the task.
3. Otherwise, the card names the project that tracks the item, or lets you pick one when several do.
   Click **Create task**. acorn makes a task linked to the item and opens it on **Agents**, with the
   item as a chip that goes with your first message. It waits only in that task.

**Run workflow** picks a workflow to start on the item instead
([Workflows and plugin panels](/docs/browser-extension/workflows-and-plugin-panels/)).

Pressing **Create task** again after a slow answer doesn't make a second task: acorn answers with the
one it made. The card closes when you leave the item's page, unless you've started filling it in.

## Match a page to its task

The extension knows which task a page belongs to from what each task already records: a task made from
a pull request knows that pull request's address, a task linked to a Linear issue or Rollbar error knows
the item's, and a plugin can publish the address of a task's running app. The pull request's address
covers its tabs, such as **Files changed**.

The matching happens in the browser, against a list the Node sends of its tasks and their addresses.
The page's address goes to the Node only when a handoff looks the item up.

## This page

On a page that belongs to a task, the panel opens on that task. **Back** goes to Home, whose **This page**
section says what acorn knows about the page beside the panel:

<SidebarPicture id="sidebar-home" />

- **A task holds it.** One row with the task's agents, its project, and its branch. Click it to open the task.
- **An item no task holds.** The handoff card. When several plugins match the page, or the Node is
  offline, **Look up in Acorn** opens it.
- **A project's site.** A project picker with the projects its sites suggest first, the project's open
  tasks, and **New task in Acorn**
  ([Project sites](/docs/browser-extension/project-sites/)).

A page that's none of these has no **This page** section.

## The branch marker

On a task's running app, such as a local development server a plugin started for the task, the
extension draws a small marker in the page's bottom-right corner: the task's branch and the app's state,
such as **running**. Its menu has **Show in side panel**, **Ask about an element**, **Open in Acorn**,
**Copy Acorn link**, and **Hide on this site**. The site needs page access, as a chip does.

## Limits

- Firefox opens its panel only from the toolbar, so there a chip's click opens its menu, which says to
  click Acorn in the toolbar.
- **Open in Acorn** needs a desktop app that opens `acorn://` links, which only a release build does. An
  extension from the development loop, `pnpm dev:extension`, offers **Copy Acorn link** instead.
- The panel shows no item state, such as a pull request's checks. Open it in the desktop app for that.
