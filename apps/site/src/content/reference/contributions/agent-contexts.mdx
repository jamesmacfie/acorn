An agent context is a source a person can reference in an agent message. They type `#` and your
keyword, such as `#acme:login-bug`, or tick an item under **Context**. Your first route lists the
items. When the message is sent, acorn asks your second route for the text and attaches it, stamped
with your plugin and the time.

## A minimal example

```json manifest
{
  "node": "./node/index.js",
  "contributions": {
    "agentContexts": [
      {
        "id": "issues",
        "label": "Acme issues",
        "options": "/v1/p/acme/context/options",
        "capture": "/v1/p/acme/context/capture"
      }
    ]
  }
}
```

## A fuller example

```json manifest
{
  "node": "./node/index.js",
  "contributions": {
    "agentContexts": [
      {
        "id": "issues",
        "keyword": "acme",
        "label": "Acme issues",
        "description": "Attach any Acme issue, linked to this task or not.",
        "search": true,
        "options": "/v1/p/acme/context/options",
        "capture": "/v1/p/acme/context/capture"
      }
    ]
  }
}
```

## Fields

{/* facts */}

A reserved or taken keyword is bound as `<pluginId>-<keyword>`. With `search`, your options route
gets what the person typed as `query`, so it can answer matches beyond what it would list.

## In the terminal

The agent composer is the same in the terminal client, so the entry is there too.
